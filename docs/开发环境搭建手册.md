# Smart Site O · 开发环境搭建手册

> 适用对象：第一次在本机（Windows）部署 ss-scada 源码开发环境的工程师。
> 目标：从零完成代码获取 → 依赖安装 → 服务启动 → 首次登录。
> 相关文档：[README.md](./README.md) · [01-环境搭建与启动](./01-getting-started.md) · [02-后端开发](./02-backend.md) · [03-前端开发](./03-frontend.md) · [04-常见问题排查](./04-troubleshooting.md)

## 0. 环境概览

| 组件 | 说明 |
| --- | --- |
| 操作系统 | Windows 10/11（本手册以 Windows 为例） |
| 代码仓库 | `ss-scada`（前端 `ss-editor` + 后端 `ss-services/ss-node` 两个 pnpm 工作区） |
| 前端 | Vue 3 + Vite 5 + Pinia + Naive UI + ECharts + Monaco |
| 后端 | NestJS 10 + TypeORM + SQLite3 + Socket.IO + ioredis + Swagger |
| 包管理器 | pnpm（lockfile v9.0，全局 pnpm 10.x 兼容） |

## 1. 硬件与软件前置条件

| 依赖 | 版本要求 | 用途 | 安装方式 |

> pnpm --version

## 2. 获取代码

```bat
:: 若尚未克隆（示例为 gitee 远程，可替换为你的仓库地址）
git clone https://gitee.com/stuhu/ss-scada.git
cd ss-scada

:: 确认当前分支（默认 master）
git branch --show-current
```

仓库关键路径：

```
ss-scada/
├─ bin/                     启动 / 安装脚本
├─ docs/                    本文档与开发指引
├─ ss-editor/               前端工作区
└─ ss-services/ss-node/     后端工作区
```

---

## 3. 安装包管理器（pnpm）

若尚未安装 pnpm：

```bat
npm i -g pnpm@10
```

> ⚠️ **pnpm 自管理版本问题（已规避，勿删配置）**
> 项目 `package.json` 用 `packageManager` 锁定了 pnpm 版本。pnpm 默认会尝试在
> `node_global\.tools` 下自动安装该版本，部分机器因此目录受保护而报
> `EPERM` 错误。仓库已在 `ss-editor/.npmrc` 与 `ss-services/ss-node/.npmrc` 中写入
> `manage-package-manager-versions=false` 关闭该行为。**请勿删除这两行**，否则新环境会再次踩坑。

---

## 4. 安装依赖

推荐一键安装（前端 + 后端）：

```bat
bin\install-deps.bat
```

脚本等价于分别执行：

```bat
cd ss-editor            && pnpm install
cd ss-services/ss-node  && pnpm install
```

安装过程会拉取约 16 个后端库包与若干前端包，并编译原生模块。若 `pnpm install` 在某个原生模块处报错（node-gyp 相关），请回到 **步骤 1** 确认 VS Build Tools 与 Python 已正确安装，重跑即可。

> 可复现安装（CI 等）：在两个工作区分别加 `--frozen-lockfile`。

## 5. 配置环境变量（.env）

后端使用多 env 文件加载（见 [02-后端开发](./02-backend.md)），开发期加载顺序：

```
.env.local（本地覆盖，gitignore，可选） → .env.{productMode} → .env.base
```

首次可这样初始化：

```bat
cd ss-services/ss-node
:: 复制模板为本地文件（.env.local 不入库，存放本地密钥/覆盖）
copy .env.example .env.local
:: 或直接基于示例模式文件调整
copy .env.dev .env.local
```

常用变量（`ss-services/ss-node/.env.base` 与 `.env.dev/.env.data` 中已带默认值，**通常无需修改即可本地启动**）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | 4000 | 后端 HTTP 端口 |
| `APP_PRODUCT_MODE` | full | full / scada / data（控制加载哪些模块） |
| `JWT_SECRET` | 内置默认 | 生产请替换 |
| `INFLUXDB_URL` | http://localhost:8086 | 时序库（未部署可不改，仅 data 模块用到） |
| `CORS_ORIGINS` | 含 5173/4000 | 前端跨域白名单 |
| `LOG_DIR` | `ss-run/.../logs` | 日志目录（自动创建） |

前端 env（`ss-editor/apps/web/.env.development`，已随仓库提供）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `VITE_PORT` | 5173 | 前端开发端口 |
| `VITE_API_BASE_URL` | http://localhost:4000 | 后端地址（Vite 代理目标） |
| `VITE_DEBUG_SKIP_AUTH` | true（development） | 仅开发跳过鉴权；后端不识别 mock token，禁用于生产 |

## 6. 启动服务

### 6.1 启动后端

```bat
bin\start-backend.bat
```

脚本分阶段执行（日志前缀 `[STARTUP] Phase A/B/C/D`）：

1. **Phase A** `pnpm install`
2. **Phase B** `pnpm build`（`pnpm -r build`，构建全部包 + 应用，首次较慢）
3. **Phase C** 拷贝 SQL 初始化脚本到 `ss-run/ss/data/init/`
4. **Phase D** `nest start --tsc --watch` 热重载

首次构建若报 `TS2307: Cannot find module '@ss-node/...'`，通常是循环依赖导致拓扑序错乱，按顺序手动构建关键包后再全量构建即可，详见[04-常见问题排查 第 2 条](./04-troubleshooting.md)。

### 6.2 启动前端

另开一个终端：

```bat
bin\start-frontend.bat
```

等价于 `pnpm --filter scada-editor-web dev`（Vite，默认 5173）。启动后访问 http://localhost:5173 。

### 6.3 一键全栈（可选）

```bat
bin\start.bat
```

## 7. 首次运行 · 初始化向导

新仓库数据库为空，后端处于「未初始化」状态，直接登录会返回 **401**（属正常）。

1. 浏览器打开 http://localhost:5173 ，前端会引导进入 **初始化向导（/setup）**。
2. 依次完成：
   - **Step 1 创建管理员账号**（必填用户名/密码/邮箱）
   - **Step 2 基本配置**（站点名、时区、语言）
   - **Step 3 数据配置**
   - **Step 4 完成**
3. 用刚创建的管理员账号登录。

> 命令行快速建管理员（等价 Step 1）：
> ```bash
> curl -X POST http://localhost:4000/api/v1/setup/step1 \
>   -H 'Content-Type: application/json' \
>   -d '{"username":"admin","password":"admin123","email":"admin@smartsite.local"}'
> ```

## 9. 搭建过程常见问题速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `pnpm` 直接报 EPERM 写 `.tools` | 自管理版本切换被拒 | 已用 `.npmrc` 关闭，勿删；否则 `corepack disable` |
| `pnpm -r build` 报 `TS2307` 找不到 `@ss-node/*` | 循环依赖拓扑序错乱 + dist 残缺 | 先按 `ss-system→ss-device→ss-alarm→ss-project` 顺序构建，再 `pnpm -r build` |
| 报找不到 `uuid` / 缺类型 | pnpm store 抽包不完整 | 改用 `import { randomUUID } from 'node:crypto'` |
| 前端 `Failed to resolve import "@/..."` | 编辑器库包 `@/` 别名在 web 上下文冲突 | 库包内改用相对路径或 `@scada-editor/*` 别名 |
| 登录 401 / 未初始化 | 数据库为空 | 走初始化向导（第 7 节） |
| 原生模块编译失败 | 缺 C++ 工具链 / Python | 装 VS Build Tools + Python 3 后重装 |
| `EADDRINUSE` 端口占用 | 旧进程未退出 | `netstat` 查占用，结束旧 `cmd`+`node` 进程树 |

详细原因与命令见 [04-常见问题排查](./04-troubleshooting.md)。

## 10. 日常开发命令速记

```bat
:: 后端
cd ss-services/ss-node
pnpm --filter ss-node-server start:dev    热重载开发
pnpm --filter <pkg> build                 单包构建
pnpm -r build                             全量构建

:: 前端
cd ss-editor
pnpm dev:full                            启动 web（development 模式）
pnpm build:web                           生产构建（--mode production）
pnpm typecheck / pnpm test               类型检查 / 单元测试
```

> ⚠️ 生产构建务必用 `--mode production`；`.env.full` 等含调试开关，误用会导致正式环境鉴权异常。
